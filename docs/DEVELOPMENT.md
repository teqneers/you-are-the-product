# Development

Everything you need to build, test and publish **You Are The Product**. For what the extension does and why,
see the [README](../README.md).

The extension is built with [WXT](https://wxt.dev) and Vite. It needs Node.js 24 or newer and npm 11 or newer.

## Develop

```bash
npm install
npm run dev            # Chrome with the extension loaded
npm run dev:firefox    # Firefox
npm test               # unit tests (also checks that every UI string exists in every language)
npm run compile        # type check
```

## Build and load

```bash
npm run build          # → .output/chrome-mv3
npm run build:firefox  # → .output/firefox-mv2
npm run build:safari   # → .output/safari-mv3
npm run zip            # store packages
npm run zip:firefox    # including the sources zip for the AMO review
```

- **Chrome:** `chrome://extensions` → Developer mode on → "Load unpacked" → `.output/chrome-mv3`
- **Firefox:** `about:debugging#/runtime/this-firefox` → "Load Temporary Add-on" → `.output/firefox-mv2/manifest.json`

## Safari

```bash
npm run build:safari                                   # → .output/safari-mv3
scripts/create-safari-project.sh                       # recreate the Xcode project in safari/
```

The Xcode project references `.output/safari-mv3`; after code changes `npm run build:safari` is enough.
Safari-specific limitations are listed in [PUBLISHING.md](PUBLISHING.md#safari).

## Languages

User-facing strings live in `lib/locales/` (one file per language, `en.ts` is the reference) and in
`public/_locales/` (store name and description). A new key needs a text in every language; `npm test` fails
otherwise.

## Data sources and licences

The JSON files in `data/` and the files in `public/geo/` are bundled as they are. They are generated by the
scripts in `scripts/` from public sources; the build does not regenerate them.

| File | Built with | Source | Licence |
|---|---|---|---|
| `data/trackers.json` | `npm run trackers` | [DuckDuckGo Tracker Blocklists](https://github.com/duckduckgo/tracker-blocklists) plus `data/extra-trackers.json` | [CC BY-NC-SA 4.0](https://creativecommons.org/licenses/by-nc-sa/4.0/) |
| `data/logos.json` | `npm run logos` | Favicons of the websites in `data/logo-sources.json`, shrunk to 32 px | belong to their owners |
| `data/vendor-names.json` | `npm run vendors` | TCF vendor ids and names from IAB Europe's [Global Vendor List](https://iabeurope.eu/vendor-list-tcf/), current and older versions (via IAB Tech Lab's mirror and iabtcf-es snapshots) | no licence stated, see [OPEN-DECISIONS.md](OPEN-DECISIONS.md#1-iab-vendor-list) |
| `data/reach.json` | `npm run reach` | [WhoTracks.me](https://whotracks.me) by Ghostery, matched via Ghostery's [TrackerDB](https://github.com/ghostery/trackerdb) | [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) |
| `public/geo/` | `node scripts/build-geo.mjs` | [DB-IP IP to Country Lite](https://db-ip.com/db/download/ip-to-country-lite) | [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) |

The names of the companies in a cookie banner's consent string come from IAB Europe's Global Vendor List. Only
ids and names are bundled (`data/vendor-names.json`, about 40 KB); the extension never downloads the list. Run
`npm run vendors` before a release to refresh it; see [OPEN-DECISIONS.md](OPEN-DECISIONS.md#1-iab-vendor-list).

Network filters such as Little Snitch or a DNS shield block many of these sources. The scripts then keep the
data of the last successful run.
